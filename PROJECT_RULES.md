# Wedding Invitation SaaS

## Tujuan Project

Membangun aplikasi Wedding Invitation SaaS yang rapi, mudah dikembangkan, dan siap diproduksi.

---

# Cara Kerja

- Kerjakan project secara bertahap sesuai roadmap.
- Satu step hanya memiliki satu tujuan.
- Jangan lompat ke phase berikutnya sebelum phase sekarang selesai.
- Setiap selesai step, update PROJECT_PROGRESS.md.

---

# Format Instruksi

Semua perubahan file harus menggunakan format berikut:

📄 File

🔍 Cari

✏️ Ganti

Atau jika membuat file baru:

📄 File Baru

📄 Nama File

📝 Isi File

Hindari instruksi seperti:
- "ubah bagian bawah"
- "tambahkan di sini"
- "sekitar baris ..."

---

# Sebelum Memberi Perubahan

- Selalu review file terbaru dari user.
- Jangan mengasumsikan isi file.
- Jika file sudah berubah, gunakan versi terbaru sebagai acuan.

---

# Coding Rules

- Jangan mengubah struktur project tanpa persetujuan.
- Jangan rename folder atau file tanpa alasan.
- Jangan refactor sebelum fitur selesai.
- Prioritaskan fitur terlebih dahulu, optimasi belakangan.
- Gunakan komponen reusable jika memang mulai banyak pengulangan.

---

# Prioritas Pengembangan

Urutan pengerjaan:

1. Function
2. Database
3. UI
4. Responsive
5. Refactor
6. Optimization

---

# Komunikasi

- Jelaskan alasan jika roadmap berubah.
- Jangan mengubah roadmap tanpa persetujuan user.
- Jika ada beberapa pilihan implementasi, jelaskan kelebihan dan kekurangannya terlebih dahulu.

---

# Dokumentasi

PROJECT_PROGRESS.md adalah sumber utama status project.

Setiap saran atau perubahan harus mengacu pada status di PROJECT_PROGRESS.md.

# Sebelum Memberi Solusi

Assistant harus:

1. Membaca PROJECT_PROGRESS.md
2. Membaca PROJECT_RULES.md
3. Membaca file yang akan diubah
4. Baru memberikan solusi

Jangan memberikan perubahan berdasarkan asumsi.
